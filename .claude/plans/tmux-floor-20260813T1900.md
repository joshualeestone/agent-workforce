# tmux built from source against the macOS floor

**Date:** 2026-08-13 afternoon
**Why:** The release gate (correctly) refuses the Homebrew-copied tmux
bundle: binaries copied off a build machine inherit its macOS as their
minimum (minos 26.0 here, measured), and dyld loads them on nothing older.
This was the one hard blocker between the merged installer (PR #34) and a
shippable `curl | sh` line. Josh's go: "heck yes, lets go!" (13:46 CT).

## The piece

`tools/build-tmux-from-source.sh`: compiles tmux 3.5a, libevent_core
2.1.12 (core only; the extra/pthreads halves fail to link under this
toolchain and tmux needs exactly core), ncursesw 6.5 (system terminfo
path baked in; libs+headers only, the database install dies on APFS and
we pin the system database anyway), and utf8proc 2.9.0, all with
MACOSX_DEPLOYMENT_TARGET read from tools/macos-floor. Sources pinned by
version and SHA-256 (trust-on-first-use measured by the script, stated
honestly; upstream cross-check is on the security list). Verification:
every artifact's floor read with the gates' own otool parse, counted per
library; all three linkages asserted (the ncurses ABI near-miss is
recorded in place); a real pty-attached session smoke with a bogus-TERM
control proving terminfo is consulted. Licences harvested verbatim from
the pinned sources; BUILD-INFO records the versions; release bundles
REQUIRE both.

## Verify

Full source rebuild green; the release bundler packs with ZERO override
flags for the first time; 529 tests + shell gate + floor/identity
consistency; 22-assertion install lifecycle harness against the
floor-built artifacts.

## Named debt

A minos stamp is a promise, not a run: one real macOS 13.x boot should
run the tarball before wide publishing (recorded in the README's release
steps). Upstream hash cross-check and artifact signing remain on the
security list.
