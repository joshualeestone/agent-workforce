## Shape of the change

- **web/index.html chrome**: `<header>` and `<nav class="tabs">` wrap in a
  sticky `.apphead` that pulls to the page edges with negative margins
  mirroring the body padding (the pack's own warning: the pull-out must track
  the stage padding exactly). The K mark (the pack's brand PNG, inlined) sits
  left of the h1 as `button.klink` whose click clicks the real Agents tab
  control, so tab bookkeeping (aria-selected, WATCH) stays in one place.
- **Toggles**: one `.viewtoggle` component, two instances, each naming its
  scope with `data-scope` (the pack's own lesson: the control names what it
  operates on). Agents toggles `#grid` between the card grid and a one-column
  compact list; projects toggles `#pj-list` between the row list and a card
  grid. Choice persists per scope in localStorage (display preference only;
  nothing leaves the machine, so the welcome promise is untouched).
- **Members wording**: "Agents on this project" becomes "Project members";
  the add row (select + confirm) hides behind a quiet "+ Add Member" button,
  which reveals it and focuses the select. Terminology sheet 2g's word.
- **Archived projects**: `engine/projects.js` gains `setArchived(id, want)`
  (mutate; sets `archived` and `archivedAt`, clears on restore). Legacy
  records without the field read as not archived via describe(), the same
  heal path descriptions use. The PUT route moves each field only when the
  body carries it (name -> rename + member re-tell; archived -> setArchived,
  no re-tell, the name did not change). The projects list renders active rows
  only; when any row is archived, a disclosure ("Show archived projects (N)",
  N derived from the rows it shows, absent at zero) reuses the removed-agents
  disclosure grammar, each row carrying its date and a Restore button. The
  archive entry point is a quiet "Archive this project" control in the
  project detail with the pack's own hint sentence ("Archiving takes a
  project off this list. Nothing in the folder changes and the agents that
  were on it stay as they are.").

## Deliberate calls

- The pack routes archiving through Project settings, which is NOT pinned
  (settings still moving). The detail-view placement here is provisional and
  flagged for Mona Lisa; the pinned pieces (disclosure, Restore, absent when
  empty, counts from rows) are exact.
- List/grid are presentation swaps over the same rendered DOM (CSS classes),
  not a second renderer: one source of truth for what a row says, two ways to
  lay it out.
- This branch will conflict with project-description in server.js PUT and
  paintProjects; both use the same conditional-fields shape so the merge is
  mechanical. Merge order: description first, then rebase this.

## Review round 1 (2026-08-14 evening)

Three blockers, all measured by the reviewer against a sandboxed server:
- The archived disclosure's empty branch hid but never cleared, so
  re-archiving the same project the same day regenerated a byte-identical
  rows string, setIfChanged skipped the rewrite, and the disclosure
  reopened on a permanently disabled Restore (a one-way door until
  reload). The empty branch now clears through setIfChanged and empties
  the label, the exact fix paintRemoved documents.
- The archive success note claimed "It is in the archived list below"
  while a failed reload rendered "we cannot read your projects" beside
  it. The note now claims only what was read (PJ_READ_FAILED gates the
  second sentence; the PUT's 200 makes "Archived <name>" a fact).
- A failed Restore was indistinguishable from an untouched button (the
  error message measured 411px off-viewport). Failure now lands on the
  button ("Restore failed. Try again"), the removal path's own rule.
Warnings: a PUT carrying no recognised field (or a wrong-typed name) is
refused, matching main's old refusal (tested); restoring the last row no
longer drops keyboard focus to body (the restored row, then the heading);
the agent card's project tags now mark archived projects; the record-level
heal is tested for truthy non-booleans and a stray date beside
archived:false (describe nulls it). Also: distinct accessible names on the
four toggle buttons, the unclosed comment parenthesis, and the empty
branch keeps text and aria in agreement.

## Review round 2 (2026-08-14 late evening)

One blocker: the Restore handler was the only loadProjects caller that
followed the await with an unconditional paintProjects(), which on a
failed re-read overwrote the honest error card with a stale list and
stranded the just-restored row behind a disabled button (the round-1
one-way door returning through the error path). It now matches its
siblings: loadProjects alone, branch on PJ_READ_FAILED, re-enable the
button and say which half failed (the PUT's 200 makes "saved" a fact; the
list's state is the card's to claim). Warnings, all fixed: the archived
disclosure is suppressed WITH the list on a failed read (a row-derived
count must not sit under "we cannot see them"); the PUT validates every
carried field before writing anything (a mixed good-name/bad-archived body
half-landed; tested); the detail view states the archived fact and flips
the control to Restore (an archived project's page offered "Archive it"
and answered a no-op as a change; reachable via pjAnswerFrom); toggle
tooltips carry the same words as their accessible names (Label in Name);
html gains scroll-padding-top so focus rescues clear the sticky bar. Nits:
the visible toggle joins the contrast sweep; empty/error cards span the
grid in grid mode. Deferred with reasons: the poll-repaint focus drop is
paintRemoved's pre-existing shape, a shared fix in its own change.
