## #153, and why one of the three is not a copy change

| | before | after |
|---|---|---|
| `:347` | "Everyone on it received it." | "Everyone on it has it waiting." |
| `:278` | "Delivered to $to." | "Placed into $to's session." |
| `:187` | "Stopped." (unconditional) | **checks, and keeps the pidfile on failure** |

✅ `:278` takes the web's own word. The screen says *"Placed into casey"*, so the
CLI and the screen now describe one state identically, which is the whole point:
an agent and an operator comparing notes must not be reading two different claims.

🛑 **`:187` was refused as a copy fix, correctly.** *"Asked it to stop"* would
have been honest about the sentence and left the defect: the pidfile was removed
whether or not the process died, so **a failed stop made Kosmos forget a live
process**. It checks now, and a failed stop **keeps the pidfile and says so** —
the record has to survive exactly when we could not do the thing.

## #122, and why the third paragraph is the whole point

The block already taught `kosmos post`. It never said **answering in place
reaches nobody**.

🔑 **A rule keyed on a CATEGORY cannot fire when the reader has filed the input
under a different one.** An agent broke this rule eleven minutes after explaining
it to two colleagues, on a message that read like a question. So the paragraph
names **the feeling** — *"reads like an ordinary question"* — which is available
to the reader at the exact moment the rule is failing, because it is what they
are experiencing. The closing *"Especially then"* is aimed at the thought that
precedes the lapse.

⚠️ **Anonymous on purpose.** Naming the agent would age badly and invite every
other reader to decide they are not that agent.

📌 **This is not claimed as the fix.** The evidence says a rule is not the
mechanism; #145's detection half is what catches the lapse. It ships because an
agent with no rule cannot even try, and it costs one paragraph in a block every
agent already receives.

✅ **It reaches existing agents too.** `healColleagues` rewrites the block from
`blockBody()` on any `syncAgent`, so the next membership sync carries it.

## Not in this release, deliberately

- **#156**, the uninstall one-way door. Real, and it is destructive code.
  Rushing a change to the thing that kills sessions is how somebody loses an
  agent they meant to keep.
- **#145's surface.** Ruled: the message's own receipt, naming the silent
  recipients, at a two-minute **render** condition rather than a timer, computed
  at render so a message answered at minute five loses the sentence. That is
  more than a line and it waits for 0.2.11.

## Verification

    yarn test    1007 pass, 0 fail
    sh -n install/kosmos

The four merged branches were combined and the suite run on the joint tree
(1006) **before** any of their PRs opened. The block pins are wrap-tolerant
(`\s+` for every space) because the block is hard-wrapped at source and the
first version broke on `"reads like an ordinary\nquestion"` — **a pin on a
phrase in wrapped prose breaks on rewrapping, which changes nothing about the
meaning.** Proven by deleting the paragraph: the pins fail with the sentences
they carry.

⚠️ **The three CLI sentences are unpinned.** Nothing in the suite asserts them,
which is how `:347` survived contradicting `chat.js`'s own table. Recorded rather
than fixed here, because the release is the priority and a shell-level pin is its
own piece of work.
